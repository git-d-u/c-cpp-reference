# フォレンジック 1. 証拠の集め方の基本

[目次](../index.md) | [次: OWASP に基づくログと調査 →](02-owasp-logging.md)

---

> この章は、インターネットの標準文書 **RFC 3227「Guidelines for Evidence Collection and Archiving」（BCP 55、2002年）** の内容をもとにしています。RFC 3227 自身も「厳密に従うことを求めるものではなく、法域によっては合わない場合がある」としています。実際の事件で証拠として使う場合は、法務担当や法執行機関に手順を確認してください。
>
> OWASP には、フォレンジック（証拠の収集・解析）を直接扱う資料は見つかりませんでした。OWASP が扱っているのは「調査に耐えるログの残し方」で、[2章](02-owasp-logging.md) にまとめています。

## 1.1 フォレンジックとは

**デジタル・フォレンジック** は、コンピューターやネットワークに残った記録を、**後から第三者が検証できる形で** 集め、調べ、報告することです。

- 「何が起きたか」を明らかにするだけでなく、「その調べ方が正しく、証拠が途中で変わっていない」と説明できることが重要です。
- そのため、調査の手順そのものを記録し、証拠を変えないように扱います。

## 1.2 収集の原則（RFC 3227）

1. **揮発性の高いもの（すぐ消えるもの）から順に集める**（1.3）
2. **分析より先に集める**。調べながら触ると、証拠が変わってしまう
3. **詳しいメモを日時付きで取る**。可能なら操作を自動で記録する（`script` コマンドなど）
4. **システムの時計と UTC（協定世界時）とのずれを記録する**。各記録の時刻が UTC か現地時刻かを明記する
5. **データの変更を最小限にする**。ファイルを開くだけでも「最終アクセス日時」が変わることがある
6. **外部から変更される経路を断つ**。ただし、ネットワークを切ると証拠を消す仕掛け（デッドマンスイッチ）が動く場合もあるので注意する
7. **ビット単位のコピーを取り、解析はコピーに対して行う**
8. **数年後に証言できるように記録を残す**

## 1.3 揮発性の順序

RFC 3227 が「一般的なシステムの例」として示している、消えやすい順の一覧です。上から順に集めます。

| 順番 | 対象 | 例 |
|------|------|----|
| 1 | レジスタ、キャッシュ | CPU の中の値 |
| 2 | ルーティングテーブル、ARP キャッシュ、プロセスの一覧、カーネルの統計、メモリ | 実行中のプロセス、ネットワーク接続、メモリの中身 |
| 3 | 一時ファイルシステム | `/tmp`、`/run`、Windows の `%TEMP%` |
| 4 | ディスク | ハードディスク、SSD |
| 5 | システムに関係するリモートのログ、監視データ | ログサーバー、SIEM |
| 6 | 物理的な構成、ネットワークの構成 | 配線、ネットワーク図 |
| 7 | 保管用の媒体 | バックアップテープなど |

```
すぐ消える ◀──────────────────────────────────────────▶ 長く残る
 メモリ・プロセス・通信 → 一時ファイル → ディスク → 外部のログ → 構成 → 保管媒体
 （電源を切ると消える）                              （残っている）
```

!!! danger "収集が終わるまで電源を切らない"
    RFC 3227 は、収集が終わる前にシャットダウンしないよう求めています。電源を切ると、メモリの中身、実行中のプロセス、ネットワーク接続などの情報（1〜2番）がすべて失われます。

## 1.4 やってはいけないこと（RFC 3227）

| やってはいけないこと | 理由 |
|------------------|------|
| 収集が終わる前にシャットダウンする | 揮発性の高い証拠が消える |
| 調べるシステムの上のプログラムを信用する | 攻撃者に置き換えられている可能性がある。ツールは読み取り専用の媒体から実行する |
| `tar` や `xcopy` など、全ファイルのアクセス日時を変えるプログラムを使う | 「いつ触られたか」という証拠が上書きされる |
| 原本を直接調べる | 調べる操作で証拠が変わる。コピーで調べる |

## 1.5 証拠に求められる条件

RFC 3227 は、証拠が満たすべき条件として次の5つを挙げています。

| 条件 | 意味 |
|------|------|
| Admissible（許容性） | 法廷などで証拠として認められる形で集めている |
| Authentic（真正性） | 証拠と事件の関係を示せる |
| Complete（完全性） | 一部だけでなく、全体の経緯を示している |
| Reliable（信頼性） | 集め方や扱い方に、真正性を疑わせる点がない |
| Believable（説得力） | 判断する人が理解し、信じられる |

さらに、収集の方法は **透明で再現できる** ことが求められます。独立した専門家が同じ方法を試せるように、手順を記録します。

## 1.6 証拠保全の連鎖（Chain of Custody）

証拠を「誰が・いつ・どこで・どう扱ったか」を、途切れなく記録します。記録が途切れると、途中で改ざんされた可能性を否定できなくなります。

RFC 3227 が記録すべきとしている項目をもとにした記録票の例です。

| 項目 | 記入例 |
|------|-------|
| 証拠の番号 | E-001 |
| 内容 | web01 の /var/log/auth.log のコピー |
| 発見・収集した場所 | サーバールーム、web01 |
| 日時（UTC と現地時刻） | 2026-11-16 01:23 UTC（10:23 JST） |
| 収集した人 | `<担当者名>` |
| ハッシュ値（SHA-256） | `<ハッシュ値>` |
| 扱った記録 | 誰が、いつ、何のために触ったか |
| 保管者・保管場所・保管方法 | 施錠された保管庫、アクセスは記録する |
| 引き渡し | 日時、相手、方法（運送の追跡番号など） |

## 1.7 ハッシュ値で「変わっていないこと」を示す

収集した直後にハッシュ値を計算して記録しておくと、あとで同じ値になることで「中身が変わっていない」ことを示せます。

```bash
# Linux
sha256sum auth.log > auth.log.sha256     # ハッシュ値を計算して保存
sha256sum -c auth.log.sha256             # あとで照合する（OK と表示されれば同じ）
```

```powershell
# Windows（PowerShell）
Get-FileHash .\Security.evtx -Algorithm SHA256
```

> MD5 や SHA-1 は、意図的に同じハッシュ値を作る攻撃が知られているため、新しく記録するなら SHA-256 などを使います。

## 1.8 時刻の記録

調査では、複数の機器の記録を時刻で並べて「何が、どの順番で起きたか」（タイムライン）を組み立てます。機器ごとに時計がずれていると、順番を間違えます。

```bash
date -u                       # 今の UTC 時刻
date                          # 今の現地時刻
timedatectl                   # タイムゾーンと時刻同期の状態（systemd の環境）
```

```powershell
Get-Date -Format o            # 現地時刻を ISO 8601 形式で（タイムゾーンのずれも表示）
(Get-Date).ToUniversalTime()  # UTC
```

- 調べる機器の時刻と、正確な時刻（自分の記録用の時計）との差を、最初に記録しておきます。
- ログの時刻が UTC か現地時刻かを確認します。Linux の syslog 形式（`Nov 10 09:00:01`）には年もタイムゾーンも書かれていない点に注意します（[Linux 3章](../linux/03-logs.md)）。

## 1.9 調査の流れ（このサイトの他の章との対応）

| 段階 | やること | 関連する章 |
|------|--------|----------|
| 準備 | 調査用のツールを読み取り専用の媒体に用意する。記録用の時計を合わせる | — |
| 揮発性の高い情報の収集 | プロセス、ネットワーク接続、ログインしているユーザー | [Linux 2章 2.6](../linux/02-security.md)、[Windows 2章 2.5](../windows/02-security.md) |
| ログの保全 | ログをコピーし、ハッシュ値を記録する | [Linux 3章](../linux/03-logs.md)、[Windows 3章](../windows/03-logs.md) |
| 解析 | コピーに対して、ログを絞り込み・集計する | [Linux 6章](../linux/06-log-processing.md)、[2章](02-owasp-logging.md) |
| 報告 | 手順、証拠の記録票、分かったことをまとめる | — |

!!! warning "許可された範囲で行う"
    調査は、組織の正式な依頼と権限の範囲で行います。他人のシステムや、許可のないデータを調べてはいけません。
